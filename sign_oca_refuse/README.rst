This module lets a signer refuse a sign request instead of signing it.

The signer gives a mandatory reason, at most 2000 characters long, as a
text signed in the document. The request moves to the new state
*Refused* and nobody can sign it any more. The refusal is written in the
activity log of the request, and posted in its chatter, which notifies
the responsible user of the request.

.. IMPORTANT::
   This is an alpha version, the data model and design can change at any time without warning.
   Only for development or testing purpose, do not use in production.
   `More details on development status <https://odoo-community.org/page/development-status>`_

Usage
=====

Refuse a document
-----------------

- Open the signing page of a request (from the email or from the
  portal).
- Press **Refuse** in the top right corner.
- Write why you refuse to sign the document, then press **Refuse**.
- The page then shows that the document is refused. Every other signer
  that opens the document sees the same page.

Follow refused requests
-----------------------

- The responsible user of the request gets the reason in the chatter of
  the request.
- The reason and the date of the refusal show in the list of signers of
  the request.
- Use the *Refused* filter of Sign / Requests, or of the portal list of
  signature requests.

For developers
--------------

- ``sign.oca.request.signer._before_refuse(reason)`` runs once the
  refusal is accepted, before anything is written: a change made there
  (such as the signer's partner) is what the log, the chatter message
  and ``_on_refuse`` see.
- ``sign.oca.request.signer._on_refuse(reason)`` runs once the refusal
  is written, in the same transaction: override it to react to a
  refusal.
- ``refused_on`` and ``refuse_reason`` are written by ``action_refuse``
  only.
- ``sign.oca.request.signer._check_can_refuse()`` raises when the signer
  may not refuse; by default a signer may refuse exactly when it may
  sign (``_check_can_sign``).
- The JSON route ``/sign_oca/refuse/<signer_id>/<access_token>`` takes a
  ``reason`` parameter and uses the same access check as the other
  ``/sign_oca/*`` routes.
